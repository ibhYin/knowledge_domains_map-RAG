## 范围与取舍

本轮处理一个 P0 和七个 P1：提示词模板、原始消息恢复、失败状态、共享默认元数据、GraphML 导出、来源漏报、别名归并及文档删除。顺带增加删除／清图／建图必要的互斥与失效保护。

保留现有 FastAPI、LangChain、NetworkX、Vue 与文件存储。复用标准库和已安装依赖，不增加图数据库、任务队列、缓存服务、Agent 或通用存储抽象。

原文引用、混合检索、评测集属于之后的能力升级；本轮不借修 bug 扩成 RAG 重构。`max_nodes` 的 P2 检查可以继续失败，但必须明确记录，不能把全部检查声称为通过。

最重要的简化：**删除任一文档后，使整张图谱失效，保留其余文档与分块，由用户重新点击构建。** 当前数据没有保留逐 chunk 的结构化抽取记录，精确撤销来源、别名、描述和权重容易漏事实。对小语料 Demo，全图重建更容易正确实现；代价是剩余文档要重新调用模型。需要频繁删除或抽取成本明显增加时，再引入抽取结果缓存和重放合图。

## A｜P0：JSON 示例被当作模板变量

**问题。** system 提示词含 JSON 大括号，通过字符串 tuple 传给 `ChatPromptTemplate` 后被当作模板解析，当前环境在请求模型前就失败。

**最小改动。** 在 `EntityExtractor._get_chain` 与 `QueryEntityExtractor._get_chain` 中，将固定 system 内容改成 `SystemMessage(content=...)`。human 继续使用 `{text}` 模板。不改提示词语义，不批量手工转义，不替换 LangChain。

**修改位置。** [extractor.py](/Volumes/xiaoPai/Documents/RAG+Konwledge_domains_map/src/graphrag/llm/extractor.py:98)。全文搜索 `ChatPromptTemplate.from_messages`，确认其他使用方式；回答提示词当前无 JSON 示例，无需机械修改。

**验收。** 两条链都能构造，并将含中文、引号、花括号的输入原样送给假模型；system 的 JSON 示例保持原文。复用已有两个 prompt 检查，并将断言重点放在生成消息内容，而非仅检查内部属性。

## B｜P1：降级解析再次异常，调用失败与无实体混淆

**问题。** `raw` 通常为 `AIMessage`，当前调用 `.get` 会报错。两条抽取链又把调用失败转换为空结果。

**最小改动。**

1. 保留 `parsed` 有效时直接返回的路径；需要降级时从消息对象读取 `.content`。
2. 仅对字符串内容使用现有 `_parse_raw_json` 和 Pydantic 校验。缺少 raw、非字符串内容或非法 JSON 都按明确失败处理，不使用 `str(list)` 强行拼接。多模态响应块不属于本 Demo 的兼容目标。
3. 文档抽取保留 `ChunkExtraction | None` 接口：合法空数组是成功，`None` 才是失败。已知模型／解析失败记录简短原因；开发期模板错误不再伪装成空抽取。
4. 问题抽取保留“成功返回实体列表”的接口：合法空数组返回 `[]`；调用／解析失败抛出带固定安全说明的 `QueryExtractionError`（继承 `RuntimeError`），用异常链保留内部原因。仅用这一种错误区分已知抽取失败，不建立异常类体系；避免 API 捕获所有 RuntimeError 而掩盖程序错误。
5. 在查询 API 的对应调用边界，将上述已知失败转为 HTTP 502。前端现有请求封装已支持显示 `detail`，复用即可；失败不写入正常问答历史。不得把任意异常全部改为 502。
6. 日志不记录 API Key 或完整请求头；接口不给出含供应商敏感配置的原始异常全文。保持现有客户端重试次数，不叠加自动无限重试。

**修改位置。** [extractor.py](/Volumes/xiaoPai/Documents/RAG+Konwledge_domains_map/src/graphrag/llm/extractor.py:113)、[查询 API](/Volumes/xiaoPai/Documents/RAG+Konwledge_domains_map/src/graphrag/api/routes.py:260)。检查 `extract()` 的全部调用点，确认 GraphSearch 允许失败向 API 传播。

**验收。** 假模型分别返回 parsed 成功、raw 合法 JSON、raw 错误 JSON、缺失 raw、非字符串 raw、调用异常。两条链的成功空结果与失败行为可区分；查询失败显示错误，不能显示“没有相关实体”。

## C｜P1：全失败任务显示完成

**问题。** `build_graph` 不论失败比例，都最终回报 `done`。

**状态约定。**

| 条件 | 状态 | 页面表现 |
|---|---|---|
| 无待处理 chunk | `done` | 无需处理／没有可构建分块，说明具体原因 |
| 待处理非空且全部成功 | `done` | 构建完成 |
| 成功与失败都有 | `partial` | 部分完成，展示成功数和失败数，可再次构建 |
| 待处理非空且全部失败 | `error` | 构建失败，不把旧图统计当成本次成果 |
| 保存失败、意外程序错误 | `error` | 本次构建未成功完成，提示错误 |

**最小改动。** 复用已有 `processed`、`total`、`failed`、`error` 字段，明确 `processed` 表示已尝试数量、成功数为 `processed - failed`。仅在成功抽取并纳入本次保存时更新处理记录；失败 chunk 不写成功 hash。允许成功空抽取被记为已处理。

单个已知抽取失败不终止其他 chunk；意外程序错误应使任务失败，避免 catch-all 把缺陷吞成部分成功。持久化完成后再发布终态；全失败且没有新成果时保留原有图及原构建时间。第二次点击构建复用现有 hash 跳过成功 chunk、重试失败 chunk，不新增重试接口或任务队列。

前端补 `partial` 文案，任一终态都停止轮询。顺便补轮询错误处理与组件卸载时取消计时器，防止错误状态被无限等待覆盖。若有旧图，清楚区分“旧图仍可查看”和“本次构建失败”。

**修改位置。** [build_graph](/Volumes/xiaoPai/Documents/RAG+Konwledge_domains_map/src/graphrag/pipeline/service.py:58)、[任务包装](/Volumes/xiaoPai/Documents/RAG+Konwledge_domains_map/src/graphrag/api/routes.py:40)、[Graph.vue](/Volumes/xiaoPai/Documents/RAG+Konwledge_domains_map/web/src/views/Graph.vue:15)。

**验收。** 用 2 个 chunk 覆盖全成功、半失败、全失败、空待办、合法空抽取；再模拟保存异常。核对终态、成功 hash、第二次调用次数及页面提示。无需真实模型完成这些检查。

## G｜P1：别名归并取决于入库顺序

**范围。** 处理同类型、抽取结果明确给出别名的对象，例如“北京大学，aliases=[北大]”。不通过模糊相似度、额外 LLM 或百科库自动猜测实体等价。重名且没有足够信息的情况保留为已知限制。

**执行步骤。**

1. 在 GraphStore 层集中处理图节点归并；EntityResolver 负责规范化和映射。检索入口不得各自修补。
2. upsert 前同时查规范名和显式别名是否指向已有节点；收集同类型候选，不只用当前 name 查询一次。
3. 没有候选时按现有规则新建；一个候选时复用；多个候选时选择一个稳定存续 key（例如规范化 key 的字典序），迁移其他候选的入边、出边和来源后删除旧节点。展示名保留可读名称；测试不要求某个中文名称必须成为内部 key。
4. 相同 source／target／relation 的边合并来源，不覆盖整条旧边；不同关系保留平行边。归并产生的自环按现有“不允许自环”的约定丢弃并记录数量。
5. 节点与边的 source_chunks 按集合去重；将 mention_count／weight 明确定义为“支持该实体／关系的不同 chunk 数”，通过来源数量重算，防止合并或重复提交同一 chunk 时膨胀。该数值不代表置信度。
6. 描述选择先保留现有“较长描述”规则，相同长度按稳定顺序选择，避免为了本项加入摘要模型；保留所有来源。别名及旧节点规范名均映射到最终 key，把指向旧节点的已有映射一并改到最终 key，避免映射链。
7. `add_extraction` 在全部实体归并后重新计算本片段有效实体 key，再做关系端点校验，防止先前收集的 key 已被后续实体合并而导致关系丢失。
8. 显式别名发生类型冲突时不自动跨类型合并、不抢占旧映射，并给出日志。若规范名自身就与另一类型同名，明确记录当前字符串主键的限制，避免把此次小修扩成完整消歧系统。

**修改位置。** [entity_resolver.py](/Volumes/xiaoPai/Documents/RAG+Konwledge_domains_map/src/graphrag/graph/entity_resolver.py:13)、[store.py](/Volumes/xiaoPai/Documents/RAG+Konwledge_domains_map/src/graphrag/graph/store.py:43)。

**验收。** 简称先／全称先都只有一个实体；归并前两节点各有入边／出边时关系完整；重复关系来源合并但不重复计数；旧名仍可定位；同一 chunk 重放不增加权重；归并后的关系仍可通过本片段校验；类型冲突不静默合并；保存重载后映射一致。

**旧数据处理。** 不在启动时批量猜测修复旧图。对已有重复节点的 Demo 数据，备份后显式清图重建；报告中注明重建需要模型调用。新逻辑不代表可以自动修好所有历史抽取错误。

## H｜P1：删除后旧事实仍可查询

**产品行为。** 删除任一已登记文档后，清空当前可查询图、别名与 processed 记录；其他文档及 chunks 保留。页面提示“文档已删除，图谱需要根据剩余文档重新构建”。不自动触发付费模型请求。不存在的 doc_id 返回 404，不能顺带清掉图。

这会暂时移除其他文档的图谱事实，直到重建完成；这是本方案明确接受的限制，不能把它描述为精确增量删除。相比原审查报告提出的抽取缓存重放方案，本轮选择更小的实现。

**服务入口与并发。**

1. 在已有 RagService 中增加删除编排入口；API 不再直接调用 ChunkStore 删除。清图也通过同一服务层管理。
2. 复用／调整服务锁，保证建图、删文档、清图在整个操作期间互斥，不只锁单次 add_extraction。锁的获取与释放用 try/finally；不要形成外层持锁后内层重复获取普通 Lock 的死锁。
3. 构建中删除／清图明确返回 409。并发启动的额外构建任务明确进入 busy/error，不能让两个建图同时写共享图；暂不实现队列、自动等待或复用 job_id。
4. 采用粗粒度串行策略时，在本次改动处写 `ponytail:` 注释，说明单进程单写的限制以及未来读快照／持久任务的升级条件。

**删除顺序与重启保护。**

仅调用 `clear(); save(); delete_document()` 仍存在写到一半中断的问题。为避免旧图在重启后回来，使用现有 meta.json 增加一个布尔字段 `needs_rebuild`，而非建立新数据库或事务框架：

1. 校验文档存在，在执行任何文档删除前，将 `needs_rebuild=true` 原子保存到 meta。写失败则停止删除并返回错误。
2. 清空内存图、别名与 processed，保留失效标记；执行文档／分块删除并持久化空图及重置元数据。任何失败均保留失效状态，不能返回删除成功。
3. `GraphStore.load` 先读 meta。发现 `needs_rebuild=true`，忽略旧 graph.json 和旧 processed，将图视为不可用并提示重建；元数据损坏时明确报错，不静默加载旧图。
4. 首次重建必须覆盖所有剩余文档；若 API 传部分 doc_ids，明确拒绝并提示全量重建。完成全量遍历并成功保存新图后再解除失效标记。出现 partial 时允许保存成功结果，但保留失效状态，待失败部分重试成功后再恢复查询。
5. 为使重试不会反复重复抽取，同一进程可保留已成功的图与 processed；失效状态下仍不对用户开放查询。进程重启后安全地从头重建，接受这一小规模 Demo 的成本限制。
6. 使用同目录临时文件＋`os.replace` 原子写入 graph 和 meta。两个文件并不是一个事务；此处的顺序保证只针对“失效标记写入后，不再提供删除前旧图”。不声称解决普通增量构建中的所有崩溃一致性问题。

文档注册表也应原子保存。删除顺序先处理文档文件／chunk，再移除注册条目，保留失败时可重试的入口；文件已不存在时允许继续清理。删除失败时图仍失效，用户能看到错误并重试；不通过吞异常返回 200。

**查询与导出。** needs_rebuild 状态必须在 API／服务调用入口生效，覆盖问答、实体浏览、路径查询、图谱可视化与导出，不能仅把图页显示成空图却仍能下载旧 graph.json。图统计可返回“需重建”与零可用节点，健康检查仍应正常。已开始的请求不会自动被撤回；Demo 验收按顺序操作，不声称并发删除后的在途答案可撤销。

**页面。** 删除确认说明“删除该文档并使图谱失效，其余文档保留”；响应带 `graph_invalidated` 信息，Documents 页展示重建提示。Graph 页展示失效状态并允许构建；现有清图文案“清空图谱与全部数据”改为真实影响范围。历史问答作为历史快照保留并标注，不承诺历史答案随文档同步撤销。
