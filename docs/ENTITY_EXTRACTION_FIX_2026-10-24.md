# 实体抽取故障修复与真实模型验证

日期：2026-10-24。

## 实际故障

先前日志中的两次构建各有 1,823 次旧提示词模板错误。这部分源码已在 P0 修复；普通启动模式不自动重新加载源码，修复后需要重启后端。

本次用当前源码、实际模型配置和一段内置短文本重新请求模型，得到 HTTP 404。原因是项目使用 ChatOpenAI 的 OpenAI 兼容协议，而本地 `OPENAI_BASE_URL` 填成了 Coding Plan 的 Anthropic 入口：

```text
错误配置：https://ark.cn-beijing.volces.com/api/coding
正确配置：https://ark.cn-beijing.volces.com/api/coding/v3
```

协议对应关系见 [火山方舟官方文档](https://docs.volcengine.com/docs/ark/coding-plan-personal-ai-hermes-agent?lang=en)。本次没有切换成普通按量付费的 `/api/v3`，也没有更换密钥、模型或结构化输出模式。

## 修复内容

1. 仅修改本地 `.env` 的 OPENAI_BASE_URL 一行，并逐行确认其他配置保持原值。`.env` 已被 Git 忽略，提交代码不会携带密钥；其他环境需自行填写正确地址。
2. 在 README 增加协议地址说明、重启要求及单分块真实检查命令。保留通用 OpenAI 兼容客户端，不在业务代码中硬编码供应商地址或自动猜测协议。
3. 新增 [smoke_extract.py](/Volumes/xiaoPai/Documents/RAG+Konwledge_domains_map/docs/smoke_extract.py)，通过现有服务层做真实模型冒烟检查，使用临时目录，不修改原文档与图谱。
4. 重新构建 web/dist，使普通模式静态托管的页面包含之前修复的构建状态反馈；启动当前源码的本机服务。

## 真实验证

测试短文本：

> 2024年，星辰科技与清华大学在北京共同建立人工智能联合实验室。

采用模型 `deepseek-v4-flash-ga-260731`、`json_mode`、原有密钥和提取温度。首次诊断请求禁用自动重试并限制超时，以避免重复发送；冒烟脚本使用正常业务客户端。

| 检查 | 实际结果 |
|---|---|
| 原地址，同一抽取链 | HTTP 404，约 0.24 秒返回 |
| 仅更换地址后，同一样例 | 真实返回 6 个实体、6 条关系；结构化解析无错误，约 23.81 秒 |
| 通过 RagService 上传、分块与建图 | 1 个分块，任务 done、0 失败，生成 5 个节点、5 条边 |
| 从 JSON 重新加载图 | 节点／边数量一致，成功处理记录为 1 |
| 检查样例中的合作关系 | 星辰科技与清华大学之间存在 PARTNERS_WITH 边 |
| 真实问题实体抽取 | 返回“星辰科技”“清华大学”，均能定位到已加载图 |
| 离线回归 | A–C 相关 15 项检查通过 |
| 前端生产构建 | 通过；原有大包警告仍存在 |

前后两次成功调用分别得到 6／6 和 5／5，说明模型结果并非固定；这里验证的是抽取、结构校验、合图和持久化链路，没有把节点数当作质量分数。
