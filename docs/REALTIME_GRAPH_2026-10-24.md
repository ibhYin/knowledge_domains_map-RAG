## 行为

每个完成的分块先合入工作图。首个成功结果立即保存；之后新增 5 个成功分块，或有新结果等待 2 秒，满足任一条件即保存并发布。没有新结果时不重复保存；合法空抽取仅更新处理记录，不编造实体和关系。

使用标准库 wait 的超时等待检查发布条件，慢请求一直未返回时也能发布已完成结果；不依赖“下一个模型请求完成”来触发时间条件。不增加 WebSocket、消息队列或新存储服务。

每次发布生成稳定快照，保存成功后 graph_version 递增并替换对外可见图谱；保存失败不推进版本。构建继续修改工作图，不修改已发布快照。

## 接口与展示

- GET `/api/graph/viz?limit=300` 同时返回 nodes、links、stats、graph_version 和 truncated，统计与画布来自同一已保存图。读取时与发布短暂互斥，防止在一次响应内混入不同版本。
- 默认最多 300 个实体、900 条关系。实体采用稳定插入顺序，关系仅连接已展示实体，关系 ID 包含起点、终点及关系类型。界面明确给出完整统计和当前展示数量，不把预览当作完整图；完整数据仍保存。
- 进度接口返回最近已保存 graph_version。前端每 1.5 秒查询进度，有新版本才拉图；首次进入和手动刷新主动取当前图。晚到的旧版本、前一个任务的响应不覆盖当前画面；图谱更新失败时保留上一版画面并提示错误。
- 计数卡片使用画布响应中的完整 stats，标注“已保存实体／关系”；处理进度独立展示。
- GraphViz 使用稳定 series／节点／关系 ID 和 ECharts 合并更新，不再使用 notMerge=true。现有力导向实现会按节点 ID 保留位置；新增关系可引起小幅布局变化，不承诺所有节点完全静止。保留选择与视角，返回缓存页面时 resize。
- 隐藏图谱页时继续任务进度轮询，暂停画布请求／渲染；返回后读取最新快照。全局任务入口仍保留。
- 构建期间后端拒绝清图和删除文档（409），避免工作图与原文件交错修改。任务结束后的删除一致性仍按 H 方案待处理。

本次同时修正关系 tooltip 按函数调用字符串的异常，并使用 ECharts 已有 encodeHTML 转义 tooltip 动态文本。

## 启用限制

真实年报任务仍在旧进程 7027 中运行，没有重启、清空或重新提交。旧进程中的暂存图没有读取接口，不能仅修改网页就把它无损切换到新发布循环；应等这一轮完成并保存后再启动新版后端。启动新版后，可用临时小样例或新增文档验证增长，不必清空已有图谱重新演示。

图谱快照仍是内存图的完整复制与 JSON 保存，适合当前个人 Demo；规模增大后应实测复制／写入耗时再决定升级，当前不宣称 3–5 秒是任意规模的硬保证。进程意外退出时可能需要重做最后一个未保存批次；没有跨进程自动续跑、多用户版本隔离或精确文档事实撤销。
